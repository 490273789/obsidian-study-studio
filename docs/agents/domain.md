# Domain docs

Study Studio uses a single glossary at `GLOSSARY.md` and records
architecture decisions under `docs/adr/`.

Read the glossary before investigating a domain question. Use its terms in
issues, hypotheses, proposals, and test names. If a concept is missing,
check how the code uses it and raise any unresolved naming question with
the domain-modeling skill.

Read ADRs relevant to the area being changed. If a proposal conflicts with
a recorded decision, identify the ADR and explain why it merits reopening.
If the ADR directory is absent, proceed. Create the first ADR when there
is a decision to record.
