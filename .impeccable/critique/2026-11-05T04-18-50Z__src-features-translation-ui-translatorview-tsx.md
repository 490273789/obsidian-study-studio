## 整体印象

这是一个安静、可信、结构正确的对比工作台。骨架、面板、键盘语义都值得保留；它停在「展示三个答案」，没有把「选一个并送进学习流程」做成终点，而且改一个字就会把答案清空。最大的机会，是把结果变成可保留、可比较、可提交的对象。

## 做得好的

1. **全高双栏的骨架是对的。** 左右各自滚动，面板头尾始终可达，长文对照不会丢失位置；清空后焦点回到输入，撤销条在原字符数的位置出现，不产生布局跳动。
2. **并行三方案不是装饰。** 三份译文同屏、逐卡朗读/制卡/插入/复制、Token 用量，加上正确的 tablist 语义（roving tabIndex、方向键/Home/End）、`lang` 与 `aria-keyshortcuts`，让它成为真正的比较工具，而不是套壳。
3. **气质贴合「安静的学习工作台」。** 唯一实色主按钮、细边界、中文优先；空态收起暂时用不到的标签与模型计数，说明渐进披露在局部是成立的。

## 优先问题

### [P1] 编辑原文或反转方向会静默清除三份译文

**为什么重要**：`setInput()` 每次都走 `invalidate()`，后者用 `replaceResults()` 把结果全部重置为 idle；`swapDirection()` 通过 `configure()` 走同一条路（translationRuntime.ts:81、155、254-267）。显式清空有撤销，改一个字却没有；关闭最后一个视图也会清空（`attachView` 的 cleanup）。三份结果来自三次付费请求，用户损失的是钱和已经读过的内容。最糟的是，用户往往在结果消失后才发现。

**怎么修**：输入变化时保留旧结果并标「原文已修改，译文可能过期」，提供「重新翻译 / 保留对照」；换向时先确认，或给结果加方向标签；在输出页脚写明「结果只存内存，关闭视图即清除」；让「清空」与「编辑」采用同一套可逆语义。

**建议命令**：`/impeccable harden`

### [P1] 学习动作被降级为图标，结果后的层级仍停在中控台

**为什么重要**：每张卡有四个动作：朗读、制卡、插入笔记、复制；只有复制带文字（TranslatorView.tsx:366-403）。「制为闪卡」和「插入笔记」是 Study Studio 区别于通用翻译器的关键，却只剩 bookmark-plus 与 file-text 两个无字图标，靠 hover tooltip 才能读懂。成功之后，页面唯一的强调色仍是底部「翻译」按钮，结果区最弱的是下一步；峰值以 11px 的「已完成 3 个方案。」收尾。

**怎么修**：卡脚用文字按钮「制为闪卡」（secondary）与「插入笔记」（ghost），朗读/复制收为图标；成功后把「翻译」降为 secondary 的「重新翻译」，并在输出页脚给「选一份译文 → 制卡 / 插入」的下一步提示；给已复制/已插入的卡片一个持续状态，而不是 2 秒后消失。

**建议命令**：`/impeccable layout`

### [P2] 空态与清空态：引导和安抚都太弱

**为什么重要**：截图里占位符到禁用主按钮几乎是一整屏；左右两个占位提示同权重，没有示例、没有「3 个方案已就绪」、没有计费或内存提示，打开视图也不自动聚焦。清空后的撤销条只有约 24px 高、11px 灰字，「撤销」的可点击区域约 22×13px；它本应用 `--fc-accent` 着色，但这个变量全仓库只有 3 处引用、0 处定义，实际继承了 muted 灰，截图里确实没有强调色。占位符又被设成 82% 正文色（截图采样约 10.8:1，正文约 15.9:1），空态看起来像已经填了内容——这是从上一轮低对比过度矫正到了另一头。

**怎么修**：空态给 1-2 条可点击示例，并写「将并行使用 DeepSeek / 百炼 / 有道智云」；右栏空态同步写「3 个方案已就绪」；打开视图即聚焦输入；撤销做成 36-40px 高、13px 文案的条，可访问名用「撤销清空」；定义 `--fc-accent` 或改用 `--fc-primary`；占位符回到约 60-65% 正文色（仍 ≥ 4.5:1）。

**建议命令**：`/impeccable onboard`

### [P2] 失败与加载：没有就地重试，键盘焦点会丢

**为什么重要**：失败卡只有 11px 红字，没有重试；`strings.retry` 从未被使用。部分失败只在右下角写「已完成 2/3 个方案」，用户只能回到底部把三份全部重跑。加载时源 textarea 被 `disabled`（TranslatorView.tsx:593），焦点被浏览器丢回 body，完成后也不恢复；没有 `aria-busy`，慢请求看起来像卡住；语音失败只清状态、不提示。按默认亮色主题推算，11px 错误文字对比度约 4.0:1，低于 4.5:1。

**怎么修**：每张失败卡加「重试」（只跑该方案，保留已成功结果）；加载时用 readOnly + `aria-busy` 替代 disabled，完成后把焦点还给输入或移到结果状态；错误文字提到 12-13px，并按实际主题验证对比度；语音错误给一条可见消息。

**建议命令**：`/impeccable harden`

### [P2] 对比表面：两个功能静默降级，控件尺寸也不达标

**为什么重要**：`--fc-accent` 未定义让 `.diffMark` 的背景声明整条失效（只剩 1px/3px padding 和 500 字重），「词汇差异高亮」按下后几乎看不出变化；`.undoBtn` 同样失去强调色。差异的定义是「不是三份共有」，不是「这份独有」——两份共有的词也会被标亮，噪声较大，且没有图例说明颜色代表什么。tab 按钮实测约 21px 高、相邻 2px，低于 WCAG 2.5.8 的 24px；「有道智云」没有模型副标题，三张卡头高度不一致，扫读节奏被打断；模型 ID 与 Token 占了每张卡不少固定 chrome。

**怎么修**：定义 `--fc-accent`（或统一改用 `--fc-primary`）；为差异加「青色 = 仅此方案」的图例，并明确「不共有 / 独有」的语义；英文判定改成三份都不含，或按段落对齐；tab 提升到 30px 高；统一卡头高度（例如显示「有道智云 · 翻译」或预留副标题行）；把模型 ID / Token 收进 hover 或展开区。

**建议命令**：`/impeccable polish`

## 次要观察

- 整页没有 h1-h6；标题在 FlashcardHeader 的 div 里，读屏只能靠地标导航。
- `makeCard` 把 `undefined` 当成功（回调类型允许 `void`）；插入失败降级到剪贴板时仍显示 ✓ 图标，文字却说「未检测到可编辑笔记」。
- `retry`、`wordCount`、`direction` 三个字符串在视图内 0 引用；失败后的恢复入口确实缺失。
- 760px 断点在容器查询与媒体查询里各硬编码一次，和 DESIGN.md 记录的 640/1024 共享边界不一致。
- `.page` 与 `.resultStack` 双层纵向滚动，且 `overscroll-behavior-y: contain` 会在窄区间截断滚动链。
- 复制成功后按钮文案仍是「复制译文」，反馈只在卡脚停留 2 秒；改成持久的「已复制」更稳。
- 主导航的 tab 标签只有 11px；作为一级控件偏小，可考虑 12px。

## 值得考虑的问题

1. 如果只显示一份「最可能被采用」的译文，这个页面会剩下什么？三份并列是在帮学习者判断，还是把选型成本转嫁给他们？
2. 为什么清空可以撤销，而改一个字却让三份结果永久消失？结果应该被当作可回滚的版本，而不是一次性缓存。
3. 如果译文的终点不是「复制」，而是「制卡 / 插入笔记」，主按钮和视觉重心应该怎么变？
