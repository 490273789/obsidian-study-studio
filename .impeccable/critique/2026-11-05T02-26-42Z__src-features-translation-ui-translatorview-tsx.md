1. **[P1] 撤销能覆盖刚输入的新稿。** 清空后六秒内，重新输入、预填、发起新翻译或换向都不会使旧撤销失效。源码显示，点击撤销会覆盖当前原文并中止进行中的请求。换向后还可能把旧译文放回新语言标签下。把撤销绑定到清空后的会话状态，有新输入或换向时使其失效。在状态仍安全时，可以留出更充裕的恢复时间，并明确处理键盘焦点和状态播报。建议 `harden`。
2. **[P2] 翻译动作离输入太远。** 截图中，输入提示在上沿，翻译按钮和快捷键在底沿。保留两栏高度，把翻译及快捷键放在原文栏头部，底栏用于状态反馈。若保留底栏提交位置，可将快捷键提示移到输入附近。建议 `layout`。
3. **[P2] 两栏空态的视觉权重相近。** 相同底色、同位置同权重的提示削弱了「从左边开始」的指引。保留对齐的面板框架，让原文焦点明确，译文等待提示略退一层并维持可读对比度。建议 `polish`。
4. **[P2] 换向图标像语言菜单。** 原文栏复用了页面的翻译图标。它有工具提示和可访问名称，视觉上仍要猜。建议用双向箭头，并让用户扫一眼就能读出「英文 → 中文」。建议 `clarify`。

第一次使用的人需要从原文一路找到底部才看到提交。熟练用户可用快捷键绕过这段距离，快速开始下一条翻译时也更容易碰到残留的撤销。键盘及读屏用户需要确认清空后焦点落点和状态播报，这两项尚未实测。

接下来可先修撤销，或同时调整主按钮位置。若调整主按钮，可以比较放在原文栏头部与保留底栏、提示移近输入区两种方案。
